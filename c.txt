  Contexte Important pour Flutter et Hedera

  Comme nous l'avons discuté, il n'existe pas de SDK Hedera officiel en Dart/Flutter. La solution la plus robuste pour la signature
  côté client est d'utiliser les Platform Channels de Flutter pour communiquer avec les SDK Hedera natifs (Java/Kotlin pour Android,
  Swift/Objective-C pour iOS).

  Principe de la signature côté client :

   1. Le backend prépare une transaction Hedera, mais ne la signe pas.
   2. Le backend envoie cette transaction non signée (généralement encodée en Base64) au frontend Flutter.
   3. Le frontend Flutter, via un Platform Channel, transmet cette transaction non signée et la clé privée de l'utilisateur (stockée
      localement et de manière sécurisée) au code natif.
   4. Le code natif utilise le SDK Hedera natif pour signer la transaction.
   5. Le code natif renvoie la transaction signée (encodée en Base64) au frontend Flutter.
   6. Le frontend Flutter envoie cette transaction signée au backend pour soumission au réseau Hedera.

  Étape 5 : Préparer un dépôt HBAR (Nécessite une signature côté client)

  Avant de pouvoir acheter des AgriTokens, l'acheteur doit déposer des HBAR dans le HarvestVault.

   * Action : L'utilisateur entre le montant de HBAR à déposer et clique sur "Déposer".
   * Méthode HTTP : POST

   * En-têtes (Headers) :
       * Authorization: Bearer VOTRE_ACCESS_TOKEN
       * Content-Type: application/json

   * Corps de la Requête (Request Body - JSON) :

   1     {

   1     {

   3         "message": "Transaction de dépôt préparée",

   8     }

   * Action Flutter - Processus de Signature Côté Client :

       1. Récupérer la clé privée : Votre application Flutter récupère la clé privée de l'acheteur de manière sécurisée (par exemple,
          depuis flutter_secure_storage).
       2. Appel au code natif (Platform Channel) :
           * Vous devez implémenter un Platform Channel dans Flutter qui appellera une fonction native (par exemple,
             signHederaTransaction).
           * Cette fonction native recevra unsignedTx (Base64) et la clé privée de l'acheteur.
           * Code Natif (Android - Java/Kotlin) :

    1             // Exemple simplifié en Java
    2             import com.hedera.hashgraph.sdk.*;
    3             import java.util.Base64;
    4
    5             // ... dans votre méthode de Platform Channel
    6             String unsignedTxBase64 = call.argument("unsignedTx");
    7             String privateKeyString = call.argument("privateKey");
    8
    9             byte[] unsignedTxBytes = Base64.getDecoder().decode(unsignedTxBase64);
   10             Transaction unsignedTransaction = Transaction.fromBytes(unsignedTxBytes);
   11
   12             PrivateKey privateKey = PrivateKey.fromString(privateKeyString);
   13             Transaction signedTransaction = unsignedTransaction.sign(privateKey);
   14
   15             byte[] signedTxBytes = signedTransaction.toBytes();
   16             String signedTxBase64 = Base64.getEncoder().encodeToString(signedTxBytes);
   17
   18             result.success(signedTxBase64); // Renvoie la transaction signée à Flutter
           * Code Natif (iOS - Swift) : (Concept similaire avec le SDK Swift)
       3. Retour à Flutter : Flutter reçoit la transaction signée encodée en Base64.

  Récapitulatif et Prochaines Étapes pour vous

  Ce guide détaillé devrait vous donner une feuille de route claire pour l'intégration frontend.

   1. Implémentez les Platform Channels dans votre application Flutter pour la communication avec le code natif Android/iOS.
   2. Développez le code natif (Java/Kotlin pour Android, Swift pour iOS) qui utilisera le SDK Hedera natif pour :
       * Décoder les transactions non signées.
       * Charger la clé privée de l'utilisateur.
       * Signer les transactions.
       * Encoder les transactions signées.
   3. Utilisez `flutter_secure_storage` pour gérer la clé privée de l'utilisateur de manière sécurisée.
   4. Suivez ce workflow pour chaque action de l'acheteur nécessitant une interaction avec Hedera.
